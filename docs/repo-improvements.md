# Repo optimization & improvement proposal

Scope: GitHub repo hygiene + Databricks Asset Bundle quality for `poc_databricks_evalueserve`
(Chilean renewable-energy medallion DLT project, two domains: `renewable_energy_chile`,
`renewable_conglomerate_energy`). Findings below are **verified against the code**; the few
audit false-positives (e.g. "`pyspark.pipelines` is invalid" — it is a valid newer API) were dropped.

Legend: **P0** = correctness/risk (do first) · **P1** = hygiene/maintainability · **P2** = polish.

---

| 0.2 | **Runtime `NameError`** in gold weekly table: `StringType` used but never imported (only `from pyspark.sql.functions import *`). | [gold_resource.py:4,80-81](../src/renewable_energy_chile/transformations/gold_resource.py#L80-L81) | Add `from pyspark.sql.types import StringType`. |

## Deeper pass — additional findings (2026-06-17)

| # | Problem | Evidence | Fix |
|---|---------|----------|-----|
| D.1 | **Inconsistent hashing algorithm** — `anonymization.hash_key` uses **SHA-1** (`sha1`), while the resource-domain silver uses **SHA-256** (`sha2(...,256)`). SHA-1 is weak and the two domains produce non-comparable keys. | [anonymization.py:3-6](../src/helper/anonymization.py#L3-L6) vs [silver_resource.py:24](../src/renewable_energy_chile/transformations/silver_resource.py#L24) | Standardize on **SHA-256** everywhere (one shared `hash_key` helper); migrate keys in a controlled change. |
| D.2 | **Hardcoded SHA-1 country hashes** for Chile/LATAM/World — couples gold logic to the exact (SHA-1) hash impl; any change to the hash fn or entity normalization silently breaks the joins. | [gold_conglomerate.py:97-99](../src/renewable_conglomerate_energy/transformations/gold_conglomerate.py#L97-L99) | Derive the keys by **looking up entity names** in `silver_dim_country` at runtime instead of pasting literal hashes. |
| D.3 | **Hardcoded comparison entities** — `gold_different_chile` bakes in Chile/LATAM/World; not configurable or reusable. | [gold_conglomerate.py:90-106](../src/renewable_conglomerate_energy/transformations/gold_conglomerate.py#L90-L106) | Parametrize the comparison set (config/variable) so other baselines can be added without code edits. |
| D.4 | **Helper hygiene** — `special_characters`/`change_comma_to_dot` lack docstrings & type hints; `hash_key` docstring typo ("hask key"); class `Algebraic_Operation` isn't PEP8 (`AlgebraicOperation`); nested `replace(replace(replace(...)))` is hard to read. | [string_transformation.py](../src/helper/string_transformation.py), [anonymization.py:4](../src/helper/anonymization.py#L4), [algebraic_operations.py:4](../src/helper/algebraic_operations.py#L4) | Add docstrings/type hints; rename the class; flatten the nested `replace` (e.g. `regexp_replace` with a char class). These helpers are pure-Python → ideal first targets for cluster-free unit tests (see 2.4). |

## Suggested sequencing
1. **P0 batch** (one PR): commit `uv.lock` (un-ignore), fix `StringType` import, reorder CI (lint+test → validate → deploy), guard prod deploy with branch + Environment approval.
2. **P1 batch**: README rewrite, branch cleanup + protection + `CONTRIBUTING.md`, rename `piprline.yml`, delete template leftovers, harden prod target.
3. **P2 batch**: explicit imports, API standardization, typo sweep, test split, dead-code cleanup, repo furniture.
4. **D batch** (correctness-adjacent): standardize hashing (D.1), de-hardcode country keys (D.2/D.3), helper hygiene (D.4). Do D.1 carefully — it changes key values.

> These are **proposals** — no code changed. Say the word and I'll open the P0 PR first (lowest-risk, highest-value), then proceed batch by batch.
